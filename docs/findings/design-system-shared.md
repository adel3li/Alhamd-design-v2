# Detailed findings: Design system, layout and shared components

The complete list from the line-by-line read of this area, at commit `68e723a`. The items that matter most are also in [FINDINGS.md](../FINDINGS.md) with ids; this file keeps the long tail. The code is described in [05-design-system.md](../reference/05-design-system.md).

Each bullet reads: `[area] [severity] title — location — what is wrong and why — suggested direction`. Unless a bullet says otherwise it was established by reading the code, not by running it.

Slice: `src/index.css`, `src/constants/tokens.ts`, `index.html`, `public/assets/aistudio/` (two design sheets, icon palette), `src/components/common/*`, `src/components/layout/*`. Commit `68e723a`.

"Verified at run time" = observed in headless Chrome 153 against a production build (`vite build` into a scratch directory). Items that could not be confirmed are marked "unverified".

## bug

- [bug] [high] Light theme + high contrast: the high-contrast CSS variables never reach the app — src/App.tsx:112, src/index.css:31, src/index.css:324 — `html.theme-light.high-contrast` sets the variables on `<html>`, but the app root `<div>` also has class `theme-light`, and `.theme-light` re-declares the ordinary light values on that `<div>`, which every descendant inherits. Verified at run time: on `<html>` `--text-primary` is `#0d0805`, `--border-hairline` `#8c7762`, `--bg-glass` `#fff`; on the root `<div>` they are `#2a1f19`, `#dccfbe`, `#fbf8f3`; the today card rendered `rgb(251,248,243)` and the root's own `bg-[#F4EDE3]` hides the body's `#FAF7F2`. Only the class-keyed remap rules work in this mode, so GlassCard, BrandMark, ThreadProgress, charts and every inline `var(--…)` consumer get no extra contrast — remove `theme-light`/`theme-dark` from the root `<div>` (the store already sets them on `<html>`), or scope the variable block to `html.theme-light`, and add a run-time check for this combination.
- [bug] [med] ThreadProgress draws its origin dot at the wrong end — src/components/common/ThreadProgress.tsx:22-24, :42-46 — the dot is the only in-flow child of a `flex justify-end` row with `dir="rtl"`, so it sits at the left; the fill is anchored `right-0`. Verified at run time (onboarding, step 1 of 4, width 120): track x 136.7–256.7, fill 226.7–256.7, dot 136.7–143.7 — use `justify-start` (or position the dot `absolute right-0`) and add a visual test.

## performance

- [performance] [low] Tailwind scans the whole repository for the app stylesheet — src/index.css:1 — no `source()` restriction (the landing CSS has one). The build contains utilities found only in `legacy/` (e.g. `dark:bg-[#0B0C10]`), and markdown is scanned too: verified by building before and after these docs were written, the app CSS grew from 87,888 to 90,348 bytes and gained `bg-[#15152A]/95` — `@import "tailwindcss" source("./");` in `src/index.css` (plus `@source "../index.html"`).
- [performance] [low] Design references are deployed with the app — public/assets/aistudio/ — `vite build` copies two HTML sheets and ten PNGs (740 KB, verified in the build output) to `/assets/aistudio/`; nothing links to them — move them out of `public/` (e.g. `docs/design/`).
- [performance] [low] 34 cards pay for a blur that shows nothing — src/components/common/GlassCard.tsx:32 — `backdrop-blur-xl` over opaque fills creates compositing layers for no visual result — remove, or make the fill translucent.
- [performance] [low] PNG held as a base64 data URL in React state — src/components/common/ShareCardModal.tsx:318-319, :652 — `toDataURL` is synchronous and the string (only used as a boolean) stays in state until the modal closes — use `toBlob` + `URL.createObjectURL` (revoke after click) and a boolean flag.
- [performance] [low] Recharts ships in the main chunk — src/components/common/ReflectionCategoryCharts.tsx:2-18 — the main application chunk is 1,031,602 bytes with no code splitting; charts are needed only on Consistency and the Journey statistics tab — `React.lazy` the chart components.
