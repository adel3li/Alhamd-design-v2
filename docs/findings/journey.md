## bug

- [bug] [high] Each station with journal text creates two identical entries in the general journal — JPS:440-448, JPS:558-567, JSF:138-150 — `persistStationCompletion` runs at the `amal → closing` step (`onReachClosing`) and again on "العودة إلى المسار" (`onComplete`); both calls pass the same text to `addJournalEntry`, which never de-duplicates (`src/lib/store.tsx:477-508`). Replaying a completed station with its pre-filled text adds two more — add the general-journal entry once per station (for example only when `!alreadyCompleted`, or only in the reach-closing call), and make `handleSessionComplete` stop re-persisting.
- [bug] [high] Muhasaba of a non-final stage becomes unreachable if it is not saved the moment it opens — JPS:626-629, JPS:688, JPS:275-292, JPS:572-574, JMS:61-68 — `displayedStage` falls back to `currentPointer.stage`, and the pointer ignores `state.muhasaba`. After station 7 is saved (at `amal → closing`), the pointer is already in the next stage. If the user closes the muhasaba screen with X, reloads on the closing screen, or leaves the closing screen through the "previous station" button, the path shows the next stage, `revealedStages` stays at one entry so no stage pills render, and the earlier stage's muhasaba node is never shown again. `journey_stage_completed` then never fires for that stage — keep the displayed stage on the first stage with a pending muhasaba, or always list completed stages in the pills.
- [bug] [high] First-time customisation ("onboarding") never opens by itself — JPS:198, JPS:1386-1391, `src/App.tsx:66-70`, `src/App.tsx:213-216` — `showOnboarding` starts `false` and is only set by the "تخصيص" button or by the path screen's own paywall `onUnlocked`. That paywall needs `premiumStatus === false`, but `App` mounts the screen only when the dev-premium flag is already true. A new premium user lands on the default `din` + `afiyah` path at pace 1 and `alhamd:journey_onboarded:v1` stays unset — initialise `showOnboarding` from `!hasCompletedJourneyOnboarding()`, or have `App`'s `onUnlocked` request it.
- [bug] [med] Daily pace is not enforced when a station is started from the path — JPS:1306-1323, JPS:328, JPS:374-420 — with `dailyPaceReached` true the preview modal only adds a note and "ابدأ التدبر" still starts the session; `unlockedTodayCount` then exceeds `pace`. The pace only blocks the in-flow "next station" button (JPS:499-503). The strict version exists in `handleStartStation`, which nothing calls. The onboarding copy promises stations that "تُفتح لك في كل يوم" (JOB:234) — decide whether pace is a hard or soft limit, then either wire the gate into the modal button or change the copy and delete the dead function.
- [bug] [med] "إظهار النص كاملًا" is undone by the next pacing tick — JSF:84-92, JSF:486-495 — the skip handler sets `sentenceIdx` to the last clause but leaves the 2.6 s interval running; the interval's next tick calls `setSentenceIdx(sIndex)` with its own smaller counter, so on steps with three or more clauses (91 of the 140 steps used by journey stations) the text shrinks back. The same pattern is likely in `src/components/screens/ReflectionModal.tsx` (same regex at :53; rest unverified) — clear the interval and timeout when skipping, or guard with `Math.max(prev, sIndex)`.
- [bug] [med] Reopening the customisation form silently turns the reminder back on — JPS:602, JPS:347-350, JOB:41-44 — the form receives `state.reminderTime || notificationTime`. When the saved journey reminder is `null`, the app-wide time is substituted, so the switch initialises on; saving any other change then calls `setNotificationTime` and `setNotificationsEnabled(true)`. Turning the switch off never turns app notifications off — pass the journey value and an explicit enabled flag; decide whether the journey reminder and the app notification are one setting or two.
- [bug] [med] Typed journal text and muhasaba answers are lost on close without warning — JSF:62, JSF:321-328, JSF:159-167, JPS:962, JMS:29-30, JMS:61-68 — both live only in component state until the save step; X, the in-flow previous/next buttons (which remount the flow, JPS:938) and the muhasaba X all discard them — persist a draft per station/stage or confirm before discarding.
- [bug] [med] Free-station limit is not applied to the current station's start button — JPS:995-996, JPS:1306-1323 versus JPS:394-398, JPS:1330 — `isInspectBlockedByFree` is computed but only hides the pace note. A free user with two completions could start station 3 and continue; only a paywall after each completion would appear (JPS:575-579). Latent today because `App` never mounts the screen for free users (`src/App.tsx:66-70`); it becomes a paywall bypass as soon as free preview is enabled — apply the same check as JPS:1330 to the `current` branch.
- [bug] [med] Regex lookbehind at render time can crash the station flow on Safari older than 16.4 — JSF:71 — the build emits `new RegExp("(?<=[.،؟!…])\\s+")` inside the component body (seen in `dist/assets/main-*.js`), so an unsupported engine throws during render, and `src/` has no error boundary. Unverified on a device — split without lookbehind (for example match `/[^.،؟!…]+[.،؟!…]*/g`) and add an error boundary around overlays.
- [bug] [low] Daily counter is stale if the app stays open past midnight — JPS:328, `src/lib/store.tsx:194-196`, `src/lib/store.tsx:229-241`, `src/lib/journeyStore.ts:223-233` — `unlockedTodayCount` is only reset inside `loadJourneyState`/`completeJourneyStation`; the path screen never compares `lastUnlockDate` with today, so "أتممت ورد اليوم" and the blocked in-flow next button persist into the next day until some journey write happens — derive `dailyPaceReached` from `lastUnlockDate === today && count >= pace`.
- [bug] [low] Saved station journal text cannot be cleared or deleted — `src/lib/journeyStore.ts:453-459`, JPS:435-438, `src/lib/store.tsx:288-296`, `src/lib/store.tsx:510-513` — `completeJourneyStation` ignores empty text, the store's `saveJourneyStationJournal` (which can delete) is never called, and deleting the copy in the Journal tab leaves `journeyState.journal[stationId]` in place; it keeps showing in the preview modal and muhasaba list — use `saveJourneyStationJournal` on replay and offer a delete.
- [bug] [low] Analytics over-count — JPS:351-354, JPS:586-588 — `journey_onboarded` fires on every preferences edit and `journey_stage_completed` on every muhasaba save including edits; neither is guarded like `journey_station_completed` (JPS:450) — fire only on the first onboarding and when `state.muhasaba[stageId]` was previously absent.
- [bug] [low] Seven stations per stage is hard-coded — JPS:318-321, JPS:640, JPS:725, JPS:737, JPS:469, JPS:990 — fine for the current content (all four stages have seven) but a shorter stage would render empty pills and wrong totals — derive from `stage.stationBlessingIds.length`.
- [bug] [low] Counts include stations of removed stages — JPS:326, JWC:107-111, `src/lib/journeyStore.ts:421-427` — `Object.keys(state.completed).length` counts orphaned completions after a theme is deselected, so "محطات الرحلة" can read more done than total and the free-limit count is inflated — count only ids that belong to `state.stages`.
- [bug] [low] Free-tier edge: "next station (8)" offered on a completed last station — JPS:497-498, JSF:152-153, JSF:274-290 — `isNextBlockedByFree` ignores `hasNextInStage`, so `canTriggerPaywallForNext` is true on station 7. Latent (free tier unreachable) — include `hasNextInStage` in the flag.
- [bug] [low] Literal `2` instead of `FREE_STATION_LIMIT` — JPS:996 — will drift if the constant changes — use the constant.
- [bug] [low] Timers not cleared on unmount — JPS:577-579, JPS:1034 — the 450 ms paywall timeout and the 2.2 s copy-feedback timeout can fire after the screen unmounts; the result is a no-op state update on a dead component, so this is hygiene only — keep ids in refs and clear in cleanup.

## a11y

- [a11y] [med] Station preview modal lacks keyboard and focus handling — JPS:1041-1052 — `role="dialog"` and `aria-modal` are set, but there is no focus trap, initial focus, Escape handler or focus return, and the page behind stays scrollable and tabbable — use a shared modal primitive that handles focus and Escape.
- [a11y] [med] Full-screen overlays are not exposed as dialogs — JSF:236-239, JSF:312-315, JMS:51-54 — the station flow and muhasaba screen are `fixed inset-0` divs without `role`, `aria-modal`, focus management or Escape; the tab bar behind remains reachable by keyboard and screen reader — same primitive as above.
- [a11y] [med] Keyboard use of "تقديم" toggles the whole theme card — JOB:153-164, JOB:209-217 — a `<button>` is nested inside a `div[role="button"]`; the card's `onKeyDown` handles Enter/Space for any target and calls `preventDefault()`, so activating the nested button with the keyboard deselects the theme instead of reordering it (browser behaviour for the button's own activation unverified) — check `e.target === e.currentTarget`, and avoid nesting interactive controls.
- [a11y] [low] Station pill accessible name omits its state — JPS:852, JPS:883-889 — `aria-label="المحطة {n}: {title}"` replaces the visible "مكتملة / المحطة الحالية / محطة قادمة" text — drop the `aria-label` or include the state.
- [a11y] [low] Toggles and disclosure lack state attributes — JPS:650-671, JPS:693-704, JPS:1204-1214, JWC:160-181 — view switch, stage pills, tadabbur toggle and chart switch have no `aria-pressed`/`aria-selected`/`aria-expanded` — add them.
- [a11y] [low] Paced reflection text is not announced and the journal textarea has no label — JSF:378-382, JSF:423-429 — the clause-by-clause paragraph is not `aria-live`, and the textarea relies on a placeholder — add `aria-live="polite"` and `aria-labelledby` pointing at the prompt.
- [a11y] [low] Small touch targets — JPS:653, JPS:664, JPS:677, JPS:1093, JPS:1111, JPS:1124, JPS:1148, JPS:1162, JSF:173, JSF:212, JOB:213 — controls are 24–36 px, below the 44 px guideline — enlarge hit areas.
- [a11y] [low] Low-contrast small text — JSF:225, JMS:105 — `text-[#AEAECB]/65` at 10 px on `#15152A` computes to about 4.2:1 (my calculation), below 4.5:1 for small text; `/60` at 11 px is lower — use the full-opacity muted colour.
- [a11y] [low] Chart values have no text alternative — JWC:225-327 — per-day numbers are available only in a hover tooltip — add a visually hidden table or `aria-label` summary.
- [a11y] [low] Decorative check icons carry meaning without text — JMS:98, JOB:205 — the muhasaba row check and the transparent check in unselected theme circles have no accessible text; the muhasaba check is shown for every row regardless of data — mark decorative icons `aria-hidden` and tie the check to real completion.

## security-privacy

- [security-privacy] [med] Private station reflections are stored twice and one copy cannot be removed — JPS:435-448, `src/lib/store.tsx:510-513`, `src/lib/store.tsx:583-605` — text goes to `journeyState.journal` and to the general `alhamd_journal`; both are plain `localStorage` and both go into the backup export.
